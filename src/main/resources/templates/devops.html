Deploying a Spring Boot application.

Practical notes from working with Java, GitHub Actions, Docker, AWS EC2, Nginx, HTTPS and Terraform in the same learning project.

Git pushGitHub ActionsDocker HubAWS EC2Nginx + HTTPS

1. Development and source control

Write and test the Spring Boot application in IntelliJ IDEA, then push a meaningful change through Git. The existing project uses a GitHub Actions workflow to automate delivery.

2. Container build and delivery

The pipeline builds a Docker image and publishes a commit-tagged image to Docker Hub. This ties deployed images to a specific source revision.

3. EC2, Nginx and HTTPS

The Spring Boot application runs in Docker on Ubuntu EC2. Nginx handles incoming web traffic and HTTPS, while the application container is bound to the host's loopback interface.

4. Infrastructure as code

Terraform records and manages AWS infrastructure using the existing configuration and S3-backed state. Application content changes do not require running Terraform for every update.

Learning environmentThese notes describe the existing project workflow. They are not a deployment trigger and do not change live infrastructure.
